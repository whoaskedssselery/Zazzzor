# Как участвовать в Zazzzor

[English](CONTRIBUTING.md) · **Русский**

Спасибо за помощь. Здесь короткий путь от клонирования до принятого
pull request. Сами правила собраны в [`AGENTS.md`](AGENTS.md) (по-английски), стиль
кода — в [`tools/agents/STYLE.ru.md`](tools/agents/STYLE.ru.md). Люди
соблюдают их так же, как агенты. Задачи и pull request можно писать
по-русски.

Нашли уязвимость? Не открывайте задачу, а прочитайте [SECURITY.ru.md](SECURITY.ru.md).

## Подготовка

Понадобятся Go версии из `server/go.mod`, Node 22 с pnpm
(`corepack enable`) и Docker: серверные тесты запускают настоящий Postgres.
Для клиента для ПК нужны Windows, Rust и MSVC Build Tools. Один раз после
клонирования:

```bash
bash tools/agents/setup.sh
```

Скрипт ставит git-хуки, которые проверяют коммиты, и навыки для Claude
Code и Codex. Подробности в [описании инструментов](tools/agents/README.ru.md).

## Проверки

Перед отправкой в репозиторий:

```bash
bash tools/agents/check.sh
pnpm lint
```

`check.sh` запускает только то, что относится к изменению: go vet, линтер,
тесты с race и govulncheck, контракт, веб-клиент, конфигурации deploy,
крейты клиента для ПК, shellcheck, поиск секретов и проверку сообщений
коммитов. В конце он печатает таблицу PASS/FAIL. CI запускает то же самое и
кое-что ещё. Сначала пишите тест и убедитесь, что он падает по нужной
причине, и только потом добивайтесь, чтобы он прошёл.

## Сначала контракт API

[`api/openapi.yaml`](api/openapi.yaml) — источник истины для REST и
WebSocket-шлюза (`x-gateway`). Изменение поведения меняет контракт в том же
коммите. Затем обновите типы клиента и тоже включите их в коммит:

```bash
pnpm gen:api
```

CI сверяет `web/src/shared/api/schema.gen.ts` с контрактом, а серверные
тесты проверяют каждый ответ по нему.

## Тексты и переводы

Всё, что читают пользователи, есть на английском и русском. Исходный язык —
английский.

- **Веб-клиент:** `web/src/shared/i18n/locales/en/*.json`, те же ключи — в
  `locales/ru/`.
- **Клиент для ПК:** `desktop/app/src/lang.rs` (трей, окна обновления и
  страница настройки).
- **Документация:** у каждого `name.md` есть двойник `name.ru.md`, и оба
  ссылаются друг на друга в начале.

Изменение текста обновляет оба языка в одном pull request. Если один из
языков вы не пишете, отметьте это в pull request — перевод добавят.

## Коммиты

- [Conventional Commits](https://www.conventionalcommits.org/ru/), в
  повелительном наклонении, строчными буквами, не длиннее 72 символов:
  `fix(server): …`, `feat(web): …`, `docs: …`. Сообщения пишутся
  по-английски.
- Атомарные, логичные коммиты. У коммита `feat`, `fix`, `refactor` или
  `perf` больше 40 строк есть тело, объясняющее зачем. Коммитов больше 600
  строк не бывает.
- Никаких `Co-authored-by`, «Generated with» и упоминаний ИИ или
  инструментов.
- Добавляйте файлы явно, никогда `git add .` или `git add -A`.
- Не коммитьте секреты и локальное состояние агентов и редакторов.
  `check.sh` и хук pre-commit следят за этим списком.

## Ветки и pull request

1. Работайте в ветке: напрямую в `main` ничего не отправляется.
2. Запустите проверки, отправьте ветку и откройте pull request в `main`. В
   шаблоне есть короткий чек-лист.
3. Перед слиянием CI должен быть зелёным, а pull request — просмотрен.

Собственные раннеры CI описаны в
[`tools/ci/runner/README.ru.md`](tools/ci/runner/README.ru.md).
