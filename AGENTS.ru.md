# AGENTS.md

[English (основная версия)](AGENTS.md)

Общие правила для всех помощников по программированию в этом репозитории. Codex читает [английский оригинал](AGENTS.md) напрямую, а Claude Code подключает его через [CLAUDE.md](CLAUDE.md). Люди следуют тем же правилам. Также обязателен [стиль проекта](tools/agents/STYLE.ru.md), составленный по замечаниям из реальных ревью.

## Настройка

После клонирования один раз запустите `bash tools/agents/setup.sh`. Скрипт установит навыки в `.claude/skills` для Claude Code и в `.agents/skills` для Codex, а также хуки Git. Подробнее в [руководстве по инструментам для агентов](tools/agents/README.ru.md).

## Проект

Zazzzor — самостоятельно размещаемая альтернатива Discord для компании друзей. Достаточно одного домашнего сервера с Linux и Docker. Облачные сервисы не нужны.

- `server/` — модульный монолит на Go. Использует chi, pgx вместе с sqlc, миграции goose и coder/websocket. Тесты запускаются с настоящим Postgres через testcontainers.
- `api/openapi.yaml` — контракт REST и WebSocket, включая раздел `x-gateway`. Это источник истины. Меняйте контракт в том же коммите, в котором меняете поведение.
- `web/` — клиент на React 19. Слои Feature-Sliced Design проверяет ESLint. Используются TanStack Router и Query, Tailwind CSS и форматтер Biome.
- `deploy/` — стеки Compose и Swarm, Caddy, образ для резервного копирования, скрипты и руководство для владельца сервера на английском и русском.
- `desktop/` — настольный клиент Windows на Rust. Tauri оборачивает веб-клиент, захват экрана работает нативно. Все крейты собираются только под Windows.

## Навигация по коду

Если доступны инструменты CodeGraph MCP, начните с них. Перед изменением символа используйте `codegraph_explore`, изучите места его вызова и оцените влияние изменения. Для того, чего нет в графе, используйте поиск и чтение файлов.

## Правила кода

- Перед изменением прочтите модуль и следуйте его стилю. Сохраняйте именование, плотность комментариев, обёртывание ошибок через `fmt.Errorf("pkg: what: %w", err)`, обработку ошибок-сентинелов через `ToProblem` и использование `db.InTx`. Запросы sqlc хранятся в `internal/<module>/queries.sql`. Для генерации запустите `go tool sqlc generate` из `server/`. Нумеруйте миграции goose начиная со следующего номера после последней.
- Сначала ищите, что можно переиспользовать (стиль проекта, §1). Расширяйте существующий код и избегайте копий.
- В документирующих комментариях описывайте поведение простым английским языком. Историю изменений оставляйте для коммитов.
- Сначала напишите тест и убедитесь, что он падает по ожидаемой причине. Затем исправьте реализацию.
- Исходники должны обходиться без невидимых символов и управляющих символов двунаправленного текста. Собирайте такие строки из кодовых точек.
- Добавляйте зависимость только при наличии причины. Фиксируйте точную версию, выпущенную как минимум две недели назад.
- После изменения `api/openapi.yaml` запустите `pnpm gen:api` и закоммитьте `web/src/shared/api/schema.gen.ts`.

## Проверки

Перед отправкой ветки запустите `bash tools/agents/check.sh`. Скрипт выполняет применимые к изменению проверки и выводит таблицу PASS/FAIL. В число проверок входят Go vet, линтер, тесты с детектором гонок и govulncheck, контракт, веб-клиент, конфигурации развёртывания, rustfmt, clippy и тесты настольных крейтов, shellcheck, поиск секретов и проверка сообщений коммитов. CI выполняет эти и дополнительные проверки. ESLint для `web/` запускается через `pnpm lint`.

## Коммиты и ветки

- Следуйте Conventional Commits. Используйте повелительное наклонение, строчные буквы и не более 72 символов в заголовке, например `fix(server): …`, `feat(web): …`, `ci: …`. Каждый коммит содержит одно логическое изменение. Для коммита `feat`, `fix`, `refactor` или `perf` объёмом свыше 40 строк укажите причину в теле сообщения. Один коммит может содержать не более 600 строк.
- Запрещены `Co-authored-by`, «Generated with», любая атрибуция ИИ и упоминание названия инструмента ИИ.
- Добавляйте файлы в индекс поимённо. Команды `git add .` и `git add -A` запрещены.
- Работайте в ветке и открывайте pull request. Прямые отправки в `main` запрещены.
- Секреты, установленные навыки (`.claude/skills` и `.agents/skills`, которые скачивает `setup.sh`) и локальное состояние агентов и редакторов (`docs/`, `.superpowers/`, `.codegraph/`, кеши, журналы, личные настройки, `.idea/`, `.vscode/`) должны оставаться вне коммитов. [Руководство по инструментам для агентов](tools/agents/README.ru.md) перечисляет общие файлы. Этот список контролируют `check.sh` и хук pre-commit.

## Безопасность

- На машине разработки могут работать посторонние контейнеры Docker. Работайте только с контейнерами, томами и сетями, которые создали сами. Запрещено запускать `docker system prune` и `docker volume prune`.
- Значения секретов не должны попадать в вывод. В диагностике допустимы имя, длина или отпечаток ключа.
- Храните временные результаты, например журналы и диагностические пробы, за пределами репозитория.

## Навыки

Навыки устанавливает `tools/agents/setup.sh`. Они загружаются в контекст по мере обращения. Перед работой читайте их описания и применяйте все подходящие. Используйте **commit-discipline** перед коммитом, **health-review** для периодического аудита и **codegraph** для навигации. Для интерфейсов также применяйте **impeccable** и **ui-ux-pro-max**, а для ревью — **code-reviewer** и **security-reviewer**.
