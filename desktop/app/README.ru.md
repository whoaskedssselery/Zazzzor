# Zazzzor для Windows

[English](README.md) · **Русский**

Оболочка настольного клиента на Tauri 2. Она открывает веб-клиент выбранного
сервера в одном окне и добавляет значок в системный трей. Веб-интерфейс
загружается с сервера, поэтому всегда соответствует его версии.

## Сборка и запуск

Нужны Windows 10/11 x64, инструменты сборки MSVC, Windows SDK и среда
WebView2, которая входит в Windows 11.

```bash
cargo build --release
target/release/zazzzor-desktop.exe
```

Можно также использовать `cargo run`. В отладочной сборке остаётся окно
консоли. Tauri CLI и Node для сборки не нужны. Страница в `setup/` написана
на обычных HTML, CSS и JS. Для демонстрации экрана `webrtc-sys` скачивает
при сборке готовую libwebrtc (~110 МБ). Чтобы использовать локальную копию, задайте
`LK_CUSTOM_WEBRTC`. Подробнее см. в [описании демонстрации экрана](../share/README.ru.md).
Среда исполнения C подключается статически ([.cargo/config.toml](.cargo/config.toml)).

При первом запуске откроется страница «Где ваш сервер?». Введите адрес
Zazzzor, который вы открываете в браузере. Для имени хоста без схемы
подставляется `https://`, путь отбрасывается. Для локального e2e-стека
(`pnpm e2e:up` и сервер разработки `web-e2e`, см. [web/e2e/compose.yml](../../web/e2e/compose.yml))
используйте `http://localhost:4173`.

Данные хранятся отдельно для каждого пользователя Windows.

- В `%APPDATA%\app.zazzzor.desktop\settings.json` хранится адрес сервера.
  Файл `.window-state.json` в том же каталоге хранит размер, положение и
  состояние развёрнутого окна.
- В `%LOCALAPPDATA%\app.zazzzor.desktop\EBWebView` лежит профиль WebView2
  с cookie сеанса, настройками веб-клиента и выданными разрешениями.

### Особенность компьютера владельца

Запуск исполняемого файла из `WebstormProjects\projects\Zazzzor` завершался
ошибкой «Отказано в доступе» (код ОС 5). Прототип захвата через Windows
Graphics Capture там получал ту же ошибку. Каталог наследует ACL песочницы
(`CodexSandboxUsers`, SID возможности) и обязательную метку целостности с
запретом записи на более высокий уровень. Программы из этого каталога
запускаются с ограничениями. Копия того же `.exe` в другом каталоге,
например `%USERPROFILE%\zazzzor`, работает. Решение о смене меток каталога
принимает его владелец.

## Возможности

- **Сервер в отдельном окне.** Веб-клиент работает как в Chrome. Cookie
  сохраняет вход после перезапуска. Доступны шлюз через WebSocket, голос
  через LiveKit и уведомления. Браузерный `getDisplayMedia` открывает окно
  выбора WebView2, а веб-клиент использует встроенную демонстрацию экрана.
- **Разрешения.** Выбранный сервер получает доступ к микрофону, камере и
  уведомлениям без запроса WebView2, как при сохранённом разрешении в
  браузере. Для остальных страниц и разрешений действуют правила WebView2
  по умолчанию.
- **Навигация.** Страницы выбранного сервера остаются в окне приложения.
  Ссылки на другие сайты, `target=_blank` и `window.open` открываются в
  браузере по умолчанию. Команды `current_instance`, `set_instance` и
  `open_instance` доступны только встроенной странице настройки. Страницы
  сервера не могут перейти на неё.
- **[Встроенная демонстрация экрана](../share/README.ru.md).** Можно
  передавать экран или окно в разрешении до 1080p при 60 кадрах/с с
  аппаратным кодированием. Можно передать звук одного приложения или
  всей системы без звука самого Zazzzor, чтобы участники не слышали
  собственный звонок. Только страницы выбранного сервера могут вызывать
  `share_sources`, `share_thumbnail`, `share_start`, `share_stop` и
  `share_status`. Приложение выдаёт разрешение источнику выбранного сервера
  при запуске. Манифест ACL в `build.rs` требует разрешение для каждой
  команды, а сама команда повторно проверяет вызывающую страницу.
  Страница получает у сервера токен участника демонстрации
  (`POST /channels/{id}/voice/screen`) и передаёт его приложению.
  Приложение подключается только к LiveKit на том же хосте и останавливает
  демонстрацию при выходе. Страницы выбранного сервера могут получить
  список окон и начать демонстрацию без окна выбора, поэтому важно, какой
  сервер вы выбрали.
- **Глобальная клавиша «Нажми и говори».** В звонке страница вызывает
  `hotkeys_ptt`, чтобы приложение отслеживало назначенную клавишу.
  Низкоуровневый обработчик клавиатуры видит нажатие, даже когда окно
  приложения на заднем плане, например во время игры. Клавиша по-прежнему
  поступает в активное приложение. Обработчик работает, пока запрошена
  клавиша.
- **Глобальные сочетания для отключения микрофона и звука.** Страница
  передаёт через `hotkeys_toggles` сочетания из голосовых настроек,
  например `Control+Shift+KeyM`. Тот же обработчик видит нажатие в фоне.
  Удержание сочетания переключает состояние один раз.
- **Автозапуск.** Пункт «Запускать вместе с Windows» записывает команду
  с параметром `--autostart` в пользовательский ключ реестра `Run`.
  При автозапуске приложение остаётся в трее.
- **Трей.** Закрытие окна сворачивает его в трей. Чтобы открыть его снова,
  щёлкните значок левой кнопкой или выберите «Открыть Zazzzor». Пункт
  «Сменить сервер…» открывает страницу настройки с текущим адресом и
  кнопкой «Вернуться к текущему серверу». Во время демонстрации доступен
  пункт «Остановить демонстрацию», а подсказка над значком сообщает о
  трансляции. «Выйти» завершает приложение.
- **Один экземпляр.** Повторный запуск выводит существующее окно на
  передний план и завершается.
- **Состояние окна.** При скрытии окна и выходе сохраняются его размер,
  положение и состояние развёртывания. При следующем запуске они
  восстанавливаются.
- **Язык.** Страница настройки, меню трея и диалоги обновления используют
  язык веб-клиента. Пока веб-клиент впервые не передал свой язык,
  приложение использует русский, если он выбран в Windows, и английский
  в остальных случаях.

## Проверено

На компьютере владельца с локальным e2e-стеком. WebView2 управлялся через
протокол DevTools (`WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS=--remote-debugging-port=9222`),
окно приложения — через Win32.

- При первом запуске появляется страница настройки. Для `ftp://x`
  показывается ошибка, а `http://localhost:4173` сохраняется и открывается.
- На страницах сервера отклоняются вызовы `set_instance` и
  `current_instance`. Эти страницы не могут перейти внутри окна
  приложения на страницу настройки или другой источник.
- Проверены вход, список каналов, статус «В сети» при подключении к
  шлюзу и «Голос подключён» в голосовом канале LiveKit. Сеанс
  сохраняется после перезапуска.
- `Notification.requestPermission()` и `getUserMedia({audio})` получают
  разрешение без запроса. Уведомление вызывает событие `show`.
- `getDisplayMedia` ждёт выбора в диалоге WebView2. Сам диалог вручную
  не проверялся.
- Закрытие скрывает окно, оставляя процесс запущенным. Повторный запуск
  завершается и выводит первое окно на передний план. Положение, размер
  и состояние развёртывания сохраняются после перезапуска.

Осталось вручную проверить нажатия в меню трея, HTTPS-сервер с действительным
сертификатом и вид уведомления в центре уведомлений Windows. Код действий
из меню трея уже был проверен.

## Релизы

Версии настольного клиента и сервера независимы. Тег `desktop-vX.Y.Z`
запускает сборку установщика NSIS для текущего пользователя Windows.
Первым доступен английский, также можно выбрать русский. WebView2
скачивается при необходимости. Ожидаемое предупреждение SmartScreen
описано в [инструкции по установке](../../deploy/desktop.ru.md). Сертификат
Authenticode и подпись исполняемых файлов отсутствуют. Подпись обновлений
обязательна и проверяется отдельно.

Владелец уже добавил `TAURI_SIGNING_PRIVATE_KEY` и
`TAURI_SIGNING_PRIVATE_KEY_PASSWORD` в секреты репозитория GitHub.
Открытый ключ включён в `tauri.conf.json`. Не заменяйте его локальным
тестовым ключом. Приватные значения доступны только шагу сборки, отдельно
от сервера и его страниц. Процесс сборки использует Tauri CLI 2.12.4 с
проверкой контрольной суммы.

1. Выберите версию настольного клиента (первая — `0.2.0`). Обновите
   `desktop/app/Cargo.toml` и `desktop/app/tauri.conf.json` и запустите тесты
   крейта, чтобы при необходимости обновить версию корневого пакета в
   `Cargo.lock`. Разместите `CARGO_TARGET_DIR` вне рабочей копии, например
   в `%USERPROFILE%\zz-build\desktop-check`. Запустите
   `bash tools/agents/check.sh`, закоммитьте изменение версии и влейте его
   после ревью.
2. На влитом коммите проверьте, создайте и отправьте тег настольного клиента.

   ```powershell
   $tag = 'desktop-v0.2.0'
   ./tools/desktop/check-version.ps1 -Tag $tag
   git tag $tag
   git push origin $tag
   ```

3. Дождитесь завершения **Desktop release** в Actions. Перед сборкой
   процесс проверяет, что существующий тег указывает на текущий коммит и
   соответствует обоим манифестам. Перед упаковкой NSIS выполняются те же
   fmt, clippy и тесты. Отдельный каталог сборки релиза внутри
   `CARGO_TARGET_DIR` исполнителя предотвращает конфликт со сборками CI.
4. После завершения процесса проверьте черновик релиза. В нём должны быть
   непустой установщик `.exe` для x64, его `.sig` и `latest.json`.
   Проверьте размер установщика, соответствие версии в JSON тегу,
   точный адрес репозитория, тега и установщика в `platforms.windows-x86_64`,
   а также наличие там содержимого `.sig`. В описании релиза перечисляются
   только изменения в `desktop/` со времени предыдущего тега настольного
   клиента. Проверьте установку под обычной учётной записью Windows.
5. Опубликуйте черновик вручную и отметьте его как последний релиз.
   Приложение увидит его только после публикации. Проверьте открытый
   [latest.json](https://github.com/whoaskedssselery/Zazzzor/releases/latest/download/latest.json)
   и при первом реальном выпуске протестируйте обновление со старой версии.

Для повторной попытки используйте **Actions → Desktop release → Run workflow**
с существующим тегом. Повторный запуск заменяет файлы только в черновике
и отклоняет опубликованные релизы. Публикуйте черновик после завершения
сборки. Чтобы исправить опубликованный релиз, выпустите новую версию с новым
тегом. Если нужен откат, опубликуйте более новую версию с отменой проблемного
изменения. Клиент устанавливает обновления только на более новые версии.

Приложение проверяет обновления при запуске и каждые шесть часов. Перед
единственным диалогом «Да / Позже» оно скачивает обновление и проверяет его
версию и подпись minisign. «Позже» откладывает предложение до перезапуска.
Пункт «Проверить обновления» в трее использует тот же процесс и сообщает,
если установлена последняя версия. Ошибки сети и проверки подписи записываются
в `update.log` в пользовательском каталоге журналов Tauri. Адрес источника
обновлений задан при сборке приложения. Страницы сервера не получают
разрешений на обновление.
